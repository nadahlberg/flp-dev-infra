# flp-dev: a disposable, production-shaped CourtListener + MCP deployment

## Why

Parts of the CourtListener ↔ MCP OAuth flow can only be exercised by real MCP
clients (Claude.ai, Claude Desktop, Claude Code, Cursor) talking to deployed
infrastructure over HTTPS on real hostnames, and some of what needs testing
only shows up when the MCP runs as several pods behind one address. Local
Docker can't do either, and production is not the place to try ideas.

This repo stands up a small copy of both services on DigitalOcean that one
person can deploy from any branch of either app repo, seed with test users and
sample data, poke at with real clients, and tear down.

## Targets

| Service                  | Host                    | Built from                                   |
|--------------------------|-------------------------|----------------------------------------------|
| CourtListener (Django)   | https://cl.nates.ai     | freelawproject/courtlistener, any repo/ref    |
| CourtListener MCP server | https://cl-mcp.nates.ai | freelawproject/courtlistener-api-client, any repo/ref |

Both hosts are subdomains of nates.ai, which is already on DigitalOcean
nameservers; each gets its own DO Domain so nothing touches the nates.ai zone
itself.

## Architecture

Everything lives in one DigitalOcean project, **flp-dev**, managed by one
Pulumi stack (`dev`), mirroring the layout of nadahlberg/infra:

- `flp-dev-k8s` — DOKS cluster, 2 × s-4vcpu-8gb in nyc3 (two nodes so the two
  MCP pods can land on different machines). Size and count are Pulumi config.
- `flp-dev-db` — managed Postgres 17, firewalled to the cluster. One logical
  database per app: `courtlistener` and `mcp`. Apps connect as the admin user.
- `flp-dev-lb` — one DO load balancer, created by ingress-nginx. cert-manager
  with a Let's Encrypt ClusterIssuer gives both hosts TLS.
- Images are built by the deploy workflow and pushed to **GHCR**
  (`ghcr.io/nadahlberg/flp-dev-courtlistener`, `.../flp-dev-mcp`). DigitalOcean
  allows one container registry per account and `core-registry` already
  belongs to the infra repo, so this stack doesn't create one.
- Per-app Kubernetes namespaces: `courtlistener` and `mcp`.

### CourtListener (namespace `courtlistener`)

Runs in **production mode** (`DEVELOPMENT=off`, `DEBUG=off`, gunicorn via the
image's `web-prod` entrypoint) so sessions, CSRF, the SSL proxy header, OAuth
and OIDC behave the way they do on courtlistener.com. Production mode assumes
some AWS-shaped things, so a small settings overlay from this repo
(`infra/courtlistener/flp_dev_settings.py`, mounted from a ConfigMap and
selected with `DJANGO_SETTINGS_MODULE`) fills the gaps without forking CL:

- static and media files on a DO Spaces bucket (S3-compatible endpoint), with
  the CSP rewritten to allow that domain
- email to the console (pod logs) instead of SES
- the managed-Postgres port (CL only reads `DB_HOST`)
- low celery concurrency, generous API throttles

Pods and services:

- `web` — Django/gunicorn, 2 workers. `celery` — one worker on every queue.
- `redis` (Deployment), `elasticsearch` (single-node StatefulSet, 9.x, xpack
  security off, CL's synonym/stopword dictionaries mounted from a ConfigMap).
- A `bootstrap` Job runs on every deploy, before web/celery roll:
  `migrate`, `createcachetable`, `collectstatic` (to Spaces), then
  `seed.py`: the dev superuser (`DEV_USER_*`), `test1..test3` with confirmed
  emails, the MCP's confidential OAuth application (client id/secret
  generated by Pulumi and shared with the MCP), `make_dev_data` on an empty
  DB, and the ES index commands.
- Not deployed (yet): doctor, disclosure-extractor, webhook-sentry, selenium,
  webpack/tailwind watchers. Add doctor when something needs extraction.

Secrets generated by Pulumi: Django `SECRET_KEY`, a 4096-bit RSA key for
OIDC, the MCP OAuth client id/secret, Spaces keys. hCaptcha uses hCaptcha's
published test keys so registration works.

### MCP server (namespace `mcp`)

- `mcp` Deployment, **2 replicas minimum** with preferred pod anti-affinity
  across nodes, rolling updates with zero unavailable, readiness on `/health`.
  Built with `TARGET_ENV=prod` (gunicorn + uvicorn workers).
- Its own `redis` and its own logical database (`mcp`) on `flp-dev-db` for the
  OAuth token store; `storage init` runs at container start.
- Points at the deployed CL: `COURTLISTENER_OAUTH_ISSUER=https://cl.nates.ai`,
  `COURTLISTENER_API_BASE_URL=https://cl.nates.ai/api/rest/v4`,
  `MCP_BASE_URL=https://cl-mcp.nates.ai`. CL points back with
  `OAUTH2_MCP_URL=https://cl-mcp.nates.ai`.
- Pulumi generates `MCP_SECRET_KEY`, the Fernet storage key and the JWT
  signing key. Ingress disables proxy buffering and raises read timeouts for
  streamable HTTP.

## Deploying

PRs get a `pulumi preview` from `ci`; merging to `main` runs `deploy`
(`pulumi up`) directly on the push.
`deploy` can also be dispatched by hand with inputs for which repo and ref
to build each app from, so an in-progress branch (or a fork) can be deployed
without touching this repo. The defaults come from repository variables
(`CL_REPO`, `CL_REF`, `MCP_REPO`, `MCP_REF`) and fall back to
`freelawproject/*` at `main`.

GitHub Actions secrets: `PULUMI_ACCESS_TOKEN`, `DIGITALOCEAN_TOKEN`,
`GH_TOKEN` (classic PAT: repo, read:packages, write:packages),
`DEV_USER_EMAIL`, `DEV_USER_PASSWORD`; optional `CL_API_TOKEN`,
`CL_SENTRY_DSN`, `MCP_SENTRY_DSN`. Variables: `DEV_USER_NAME` (default
`dev`) plus the repo/ref variables above.

Image tags are `<app short sha>-<run number>`, so every deploy rolls the pods
even when the app sha is unchanged.

## Ad hoc work

- **Test a branch**: dispatch `deploy` with `cl_ref`/`mcp_ref` (and
  `cl_repo`/`mcp_repo` for a fork). Rolling back is dispatching again with
  `main`.
- **More users / different seed data**: edit `infra/courtlistener/seed.py`
  (it is idempotent and re-runs on every deploy) or `kubectl exec` into the
  web pod and run `manage.py` directly.
- **Real data**: `kubectl exec -n courtlistener deploy/web -- ./manage.py
  clone_from_cl ...` with `CL_API_TOKEN` set.
- **Cluster access**: `doctl kubernetes cluster kubeconfig save flp-dev-k8s`
  or `pulumi stack output kubeconfig --show-secrets`.
- **Scale the MCP**: Pulumi config `mcpReplicas` (default 2).

## Branch protection

Same ruleset as nadahlberg/infra on `main`: no deletion, no force-push,
changes through a pull request (0 required approvals), and the `preview`
check from `ci` must pass.

## Risks and open questions

- CL's migrations have never been run on DO managed Postgres 17 here; if
  something needs superuser (extensions, roles), fall back to an in-cluster
  Postgres StatefulSet for CL.
- The Spaces-backed static storage uses CL's `S3ManifestStaticStorage`
  through a non-AWS endpoint; `collectstatic` is the first thing to watch.
- ES: this deploys single-node 9.x with security off; CL's index creation
  path (`search_index --create` then `cl_index_parent_and_child_docs`) is
  invoked by the bootstrap Job but hasn't been verified in this setup.
- Cost at idle, roughly: cluster $96/mo, LB $12/mo, DB $15/mo, Spaces $5/mo.
  `pulumi destroy` removes all of it; the DO project is created by this stack.
- The repo is public. Nothing sensitive is committed; all secrets come from
  GitHub Actions or `.env`.
